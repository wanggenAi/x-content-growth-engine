## 公开工程参考

### Virality-Prediction

仓库：[remidomingues/Virality-Prediction](https://github.com/remidomingues/Virality-Prediction)

README 描述的流程是：用 Twitter API 连续采集至少数天，去重；经过固定等待窗口后更新转发量；从账号、实体和文本长度提取特征；用回归或分类器预测转发量/传播类别；再按 hashtag 汇总预测。

它的特征包括粉丝数、好友数、账号状态数、账号年龄、认证、标签、媒体、提及、链接和文本长度。这个清单提醒我们：**作者规模和分发条件必须与文本特征分开记录**。

限制也必须保留：仓库 README 写明数据是三天随机英文推文；代码使用旧 Twitter API、MongoDB/HDF5 和 Python 2 时代依赖；`regression.py` 随机打乱后切训练/测试，容易让相近事件或时间分布同时进入两侧。它适合学习流水线，不适合直接复用模型或声称预测今天的 X。

### Upworthy Research Archive

[Upworthy Research Archive](https://upworthy.natematias.com/) 和其数据论文 [Nature Scientific Data](https://www.nature.com/articles/s41597-021-00934-7) 展示了另一种可借鉴的实验结构：同一故事制作多个标题变体，保存随机化分配、曝光和点击结果，再把探索与确认分开。它是英文发布站点的点击实验，不能直接移植为中文 X 的浏览/转发因果结论；可以借鉴的是同题材变体、预注册和 holdout。

维护方的 [2024 年重要更新](https://upworthy.natematias.com/2024-06-upworthy-archive-update.html)指出，约 22% 的实验可能有随机分配问题，建议不要用 2013-06-25 至 2014-01-10 的区间作因果确认。只看旧论文而忽略数据修订，会高估证据。官网说明档案、代码和文档采用 CC-BY-4.0；这也不把其他平台的数据使用权一并授权。

## 下一轮怎样执行

1. 先选一致的目标读者：本轮测试以中文 AI/工具使用者为候选，记录为编辑假设；不把不相干生活技巧、研究元话题和产品新闻混作同一类效果。
2. 把一个真实发现写成“可核对的纠错”“具体成果演示”或“失败条件提醒”。这些方向来自查到的源代码/实验方法，仍需测试；不预先给它们任意爆帖分数。
3. 每次比较只改变一个变量：例如纠错开头与直接事实开头，其余事实、题材、图片、出处和长度尽量接近。不同独立题材构成匹配区组，避免同账号连续发布近乎重复的句子。
4. 先发布少量有证据的原创新帖，按发布后 1 小时、24 小时、72 小时保存观察时刻与原始指标。已经错过的首小时留缺失，不能用累计数补作历史数。
5. 冻结探索规则后保留较晚日期和独立作者作为复核；出现反方向结果也保存。原有 17 条混合题材帖子是可观察的历史内容，不是预注册实验。

现有 11 个外部 X 链接仍只有 1 个原文确认、0 组 READY 对照。方法与来源搜索取得进展，当前数据尚不能支持训练一个可靠的中文爆帖模型。

## 研究设计

### 1. 先定义结果

把“爆”定义为固定窗口内的结果，而不是看起来像爆帖：

- 主要结果：发布后 24 小时的浏览、转发、回复、点赞，分别保存；
- 派生比率：转发/浏览、回复/浏览、互动/浏览；浏览为缺失时不计算；
- 辅助结果：首小时指标、个人主页访问和新增关注（只有账号页面或人工截图能核对时才录入）；
- 不能把搜索摘要、相对时间或缩写数字当成精确历史指标。

### 2. 特征分层

每条帖子在看结果前标注版本化字段：

- 内容：文本长度、媒体/链接、具体场景、冲突、反常识、实用动作；
- 人性机制：身份认同、损失/风险、尴尬、愤怒、惊讶、敬畏、焦虑、归属；这只是候选机制，不是效果标签；
- 社交价值：转发是否能表达“我经历过/我懂/我站这一边”；
- 环境：作者历史基线、发布时间、话题、账号规模、是否引用/推广、首批互动；
- 证据：来源、发布时间、是否可复核、缺失原因。

账号规模、发布时间和首小时互动不能混进“文案本身”的特征，否则会把分发优势误判为写法优势。

### 3. 切分与对照

采用作者和时间双重 holdout：早期日期做探索，较晚日期做测试；能在同一作者、相近话题和相近发帖年龄内配对时才建立对照。不要随机打乱全部帖子后切分。每个候选都保留反例、删除推广/引用混杂后的敏感性结果。

### 4. 模型只做基线

先用可解释基线（中位数、逻辑回归或正则化线性模型），再比较树模型；报告基线、时间外测试、校准和不确定性。样本不足时不训练“爆帖生成器”，只做记录和下一轮预注册。任何分数都不自动把 `HYPOTHESIS` 升成 `REPLICATED` 或 `EXPERIMENT_SUPPORTED`。

## 现阶段可用结论

Berger 与 Milkman 的研究（[DOI](https://doi.org/10.1509/jmr.10.0353)）对近 7,000 篇《纽约时报》文章发现，实用价值和高唤醒情绪与更高传播相关；这不是“越极端越好”，也不证明中文 X 的因果效果。Heimbach 与 Hinz 的复核（[DOI](https://doi.org/10.1016/j.ijresmar.2016.02.004)）提示正面程度可能是倒 U 型；Hansen 等对 Twitter 的研究（[arXiv](https://arxiv.org/abs/1101.0510)）说明新闻与非新闻的情绪关系不同。

因此下一批写作测试不按“搞笑/不搞笑”分组，而按预注册机制分组：具体尴尬、身份冲突、损失/风险、反常识揭露、纯实用动作。每组保留普通对照，发布后按固定窗口记录结果。

## 不做的推断

- 不把 GitHub 项目里的旧英文数据模型当成中文 X 规律；
- 不把某篇论文的相关关系写成“保证爆”；
- 不把账号规模、平台推荐和外部事件归因给一句文案；
- 不用代理观察伪造 `human_reviewed` 或 own-post 反馈；
- 不在没有 holdout 和反例时发布“爆帖公式”。
